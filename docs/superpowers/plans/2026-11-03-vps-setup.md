# VPS Setup Scripts Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A single bash script that turns a clean Ubuntu VPS into a wstunnel+WireGuard egress server and emits one connection-bundle file for the Windows client.

**Architecture:** `setup.sh` orchestrates pure *render* functions (deterministic string generation for WireGuard confs, the wstunnel systemd unit, and the client bundle — unit-testable with bats given injected keys) and *apply* functions (package install, key generation, sysctl, NAT, systemd enable — need root, verified on a throwaway VPS/VM). The wstunnel server listens on TLS :443 and forwards **only** to the loopback WireGuard UDP port; WireGuard NATs to the egress interface.

**Tech Stack:** bash, wireguard-tools, wstunnel v11 (prebuilt binary), systemd, iptables (or nftables via iptables-nft), openssl (self-signed cert), bats-core + shellcheck for tests.

**Spec:** `docs/superpowers/specs/2026-11-03-anct-wstunnel-design.md`

## Global Constraints

- Target OS: Ubuntu LTS, clean state, run as root/sudo. One script run to completion (§4.2).
- No custom domain; self-signed TLS auto-generated (§4.4).
- Connection endpoint default is the VPS DDNS name; IP-direct selectable (§4.1).
- WireGuard address range `10.88.0.0/24`, server `.1`, client `.2` (§4.4 example; fixed here).
- WireGuard MTU small fixed value `1280`, shared via bundle (§4.3).
- wstunnel listens on `:443`; WireGuard UDP listens on loopback only, reachable only via wstunnel (§3).
- Secrets (private keys, bundle) never world-readable, never echoed to logs (anti-goal §6).
- No SNI spoofing or blocklist-evasion tricks; plain hostnames/ports only (anti-goal §6).

## Review Focus

- **Re-running setup.sh on an already-configured VPS:** must be idempotent — not duplicate NAT rules and not silently regenerate keys (which would break an already-distributed bundle). Covered by Task 5.
- **Egress interface is not `eth0`:** NAT masquerade must target the real default-route interface (cloud VPSs use `ens3`, `enp1s0`, etc.). Covered by Task 4.
- **Reboot persistence:** ip_forward, NAT rules, and both services must come back after reboot. Covered by Tasks 4 and 6.
- **wstunnel must not be an open relay:** server must restrict forwarding to `localhost:<wg-port>` only. Covered by Task 6.
- **Bundle/key file permissions:** private key in the bundle and on disk must be mode 600, owner root. Covered by Tasks 2 and 3.

## Shared Interface: the connection bundle

The bundle is the contract the Windows app (Plan B) consumes. JSON, UTF-8, mode 600, written to `./wgvpn-bundle.json` by default.

```json
{
  "version": 1,
  "server":    { "host": "<ddns-or-ip>", "port": 443, "tlsSha256": "<hex-fingerprint>" },
  "proxy":     { "host": "websec.asahikawa-nct.ac.jp", "port": 8080 },
  "wstunnel":  { "localUdpPort": 51820, "remoteTarget": "localhost:51820" },
  "wireguard": {
    "privateKey": "<client-private-key>",
    "serverPublicKey": "<server-public-key>",
    "address": "10.88.0.2/32",
    "allowedIps": "0.0.0.0/0",
    "dns": "1.1.1.1",
    "mtu": 1280,
    "persistentKeepalive": 25
  }
}
```

### Task 3: Pure render functions (`render.sh`) — confs, unit, bundle

**Files:**
- Modify: `vps/lib/render.sh`
- Create: `vps/tests/render.bats`

**Interfaces:**
- Consumes: keys from Task 2 (passed as args; render functions do no generation).
- Produces (all echo to stdout, no files, deterministic):
  - `render_wg_server_conf <server_priv> <client_pub>` → WireGuard server conf: `[Interface]` Address `10.88.0.1/24`, `ListenPort 51820`, no public bind note (bound via systemd to loopback is handled at apply); `[Peer]` client_pub, AllowedIPs `10.88.0.2/32`.
  - `render_wg_server_conf` must **not** embed PostUp NAT (NAT handled by net.sh/Task 4) — keep conf minimal.
  - `render_wstunnel_unit <wg_udp_port>` → systemd unit text running `wstunnel server wss://0.0.0.0:443` with TLS cert/key paths `/etc/wgvpn/cert.pem`,`/etc/wgvpn/key.pem` and `--restrict-to localhost:<wg_udp_port>` (verify exact v11 flag names against `wstunnel server --help`; the restriction and TLS-cert flags are mandatory).
  - `render_bundle <host> <port> <tls_sha> <client_priv> <server_pub>` → the Shared Interface JSON exactly, with fixed fields (proxy host/port, localUdpPort 51820, remoteTarget `localhost:51820`, address `10.88.0.2/32`, allowedIps `0.0.0.0/0`, dns `1.1.1.1`, mtu `1280`, keepalive `25`).
